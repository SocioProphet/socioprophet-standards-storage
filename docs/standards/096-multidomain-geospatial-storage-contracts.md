# 096 — Multi-Domain Geospatial Storage Contracts

Status: Draft v0.1
Authority: `SocioProphet/socioprophet-standards-storage`
Related: `SocioProphet/prophet-platform-standards/docs/standards/070-multidomain-geospatial-standards-alignment.md`

## Purpose

This standard defines storage, event, analytical payload, benchmark, and data-governance obligations for the multi-domain geospatial intelligence stack.

The standard covers Earth observation, space telemetry, maritime domain awareness, air-domain awareness, smart spaces, defense/public-safety governance, and multi-domain sensor fusion.

## Canonical storage formats

| Data class | Required / preferred formats |
| --- | --- |
| Event streams and operational observations | Avro event schemas; versioned topic names |
| Analytics tables and batch products | Arrow and Parquet; GeoParquet where geometry is columnar |
| Semantic/provenance overlays | JSON-LD and RDF-compatible identifiers |
| Raster and remote-sensing assets | COG, Zarr, NetCDF, and STAC catalog references |
| Vector tiles and map delivery artifacts | MVT, PMTiles, MBTiles, MapLibre style/layer manifests |
| Time-series telemetry | Parquet/Arrow partitions plus event index; bounded retention policy |
| Graph overlays | RDF/SPARQL, property graph, or hypergraph profile selected by workload gate |

## Minimum record families

The following record families MUST be standardized before implementation repos treat them as stable contracts.

- `SpaceAssetRecord`
- `OrbitEphemerisRecord`
- `GroundStationContactEvent`
- `TelemetryObservation`
- `EarthObservationProductRecord`
- `VesselTrackObservation`
- `AirTrackObservation`
- `SensorObservationEnvelope`
- `MultiDomainFusionEvent`
- `SensitiveGeoPolicyRecord`
- `MapLayerManifest`
- `RuntimeBoundaryEvidenceRecord`

## Event stream requirements

Each event stream MUST specify:

- event name and version
- producer and consumer responsibilities
- schema format and registry ID
- source license and access-control classification
- provenance reference
- timestamp semantics: observed, received, processed, published
- geospatial reference system
- geometry precision policy
- confidence and uncertainty fields
- redaction and sensitive-location handling
- retention and deletion policy

## Benchmark workloads

The benchmark harness SHOULD include workloads for:

1. STAC catalog search latency and filter correctness.
2. OSM / authoritative record conflation throughput.
3. Vector tile export latency and size.
4. AIS/LRIT/ADS-B stream ingest throughput with duplicate suppression.
5. Satellite product metadata ingest and spatial/temporal query.
6. Telemetry anomaly event indexing.
7. Multi-domain fusion query over space, air, maritime, land, and sensor observations.
8. Sensitive-location redaction correctness.
9. Offline map package generation and delta update size.
10. Replay/reconstruction of a decision card from raw source events.

## Governance obligations

All multi-domain storage contracts MUST include:

- license and attribution fields
- data-source trust tier
- privacy/safety tier
- retention tier
- export/distribution constraints
- redaction requirements
- evidence/provenance references
- runtime boundary references when generated by an executable runtime

## Implementation rule

Implementation repositories MUST NOT freeze their own independent event/storage contracts for these domains. They may add fixtures and adapters, but stable schemas must be promoted here first or explicitly reference a draft standard in this repository.
